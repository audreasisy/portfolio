1The problem

Every client order required a Purchase Order and a Completion Minutes document, prepared by hand. Each one is:

  • bilingual — Vietnamese first, English second — with fixed legal clause wording that can't drift between documents;
  • full of chained financial calculations — line amounts, subtotal, a management fee, 8% VAT, and a grand total, where one wrong figure cascades through the rest;
  • tagged with a standardized Order ID and filed in its own Drive folder.

Done manually, per order, this was slow and error-prone — and, just as importantly, locked in one person's head. There was no way to hand it off cleanly or trust that two people would produce identical documents.

2What I built

A single source-of-truth workbook where each order is entered once, paired with a one-click tool — a custom ➕ Creation menu built into the sheet. On one click, the system:

  1. creates (or safely reuses) a dedicated Drive folder for the order;
  2. copies the correct template — Account Management or KOL / influencer for the PO, plus the CM document;
  3. fills every field through merge tokens ({{CLIENT_NAME}}, {{GRAND_TOTAL}}, …) and builds the line-item table row by row;
  4. writes the folder, PO, and CM links back into the master record, so the workbook stays the single index of truth.

3Key design decisions

  • Single-entry data model. Four linked tabs — Clients & Contracts, PO Header, PO Line Items, CM Register — with a colour convention that separates manual input from auto-calculated fields, so users always know what's safe to touch.
  • Derived finance & ID logic — never hardcoded. Every total is calculated from one dataset (Amount = Unit price × Quantity → Subtotal → Management fee % → 8% VAT → Grand total). Order IDs auto-generate with a standardized single-/multi-brand syntax and an auto-incrementing sequence, so no two orders can collide.
  • Bilingual, compliance-safe output. Fixed clause wording, DD/MM/YYYY dates, and multi-currency formatting (VND / JPY / USD) that stays consistent across every generated document.
  • Layout-adaptive filling. The script locates tables by their header text rather than fixed cell addresses, so it keeps working even after the templates are restyled.
  • Built-in resilience. Per-row error handling means one bad row can't break a batch; a clear, human-readable message explains when a file can't be overwritten; validated dropdowns stop bad input at the source.
  • Safe regeneration. Editing the master and re-running cleanly replaces the old documents — old copies to Trash, links repointed, no duplicates — while signed documents stay fixed as final snapshots.

5What I owned end-to-end

I scoped the problem, designed the data model, wrote and debugged the automation, and documented it for handover. Along the way I diagnosed and fixed subtle real-world failures — inserted rows not inheriting the template's cell merges (which clipped long values), copy operations silently dropping formatting, and file-ownership blocks that stalled regeneration — turning a fragile prototype into a stable tool the team now depends on daily.
